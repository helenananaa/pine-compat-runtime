# Bounded historical intrabar requests (2026-09-25)

`request.security_lower_tf()` now accepts a nonnegative simple-int `calc_bars_count` supplied by name after the three positional arguments. Zero uses all available bars, as TradingView specifies in its [release notes](https://www.tradingview.com/pine-script-docs/release-notes/). For a positive value, historical provider-backed requests retain only the latest N requested bars before evaluating the expression, so history, `bar_index`, UDF state, and cumulative indicators begin at the bounded history origin. Earlier chart intervals return typed empty arrays. Equal chart-context requests obey the same count against the chart's historical dataset; incremental execution without a known dataset end fails explicitly for this combination. TradingView describes this parameter as a limit on requested historical intrabars in its [official limitations documentation](https://www.tradingview.com/pine-script-docs/writing/limitations/).

The tracked `security_lower_tf_calc_bars_count.pine` fixture requests a tuple of `ta.cum(close)` and `bar_index` with `calc_bars_count=2`. The runtime test proves the requested state restarts on the retained bars; a CLI run on the tracked chart/request CSVs produced plot series `[[0,2],[0,2],[null,47],[null,1]]` with no diagnostics. Its ignored output is `.local/community-coverage-20260923/lower-tf-cli-calc-bars-count-20260925.json`.

This remains a partial request implementation. The other optional request parameters, dynamic series timeframe selectors, provider-backed forming updates, collection expressions, and reference graph transfer are not admitted. The public TradingView `ta` library uses both dynamic timeframe selectors and `calc_bars_count` on `request.security` as well, so this change alone does not qualify that library. No TradingView numerical export for this fixture has been compared. Full locked seven-package test output is in ignored `.local/community-coverage-20260923/lower-tf-calc-seven-package-tests-20260925.log`.
