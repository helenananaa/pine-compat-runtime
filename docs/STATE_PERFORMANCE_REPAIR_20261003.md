# 实时绘图与大数组性能修复

本轮接续 [核心性能修复](CORE_PERFORMANCE_REPAIR_20261003.md)，处理剩余的绘图 checkpoint 和增量扫描、大数组复制、varip 恢复临时分配，以及历史树遍历和裁剪。大负载的增量更新分配显著下降；完整绘图快照仍有深复制成本，并观察到局部耗时回退，不能据此称所有路径都变快。

改动保持宿主无关，没有改变公开输出 schema、缩短测试历史或删减完整结果。本轮核心身份包含 543 个代码和测试文件，绑定 `09d6127036a5bc3489112be7dae34bef5ef4df72` 上的工作区改动，见 [源码身份](../.local/state-performance-20261003/source-identity.json)。

## 修复内容

- 六类绘图使用持久化 ID 存储。checkpoint 和输出 cursor 共享根；增量对比跳过共享子树和共享对象，仍识别同长度尾部替换、table 元属性变化及形成中撤销。polyline 淘汰使用活动 ID 索引。
- 大数组按 128 个元素分页，小数组继续使用连续 Vec。稀疏写复制页目录和一个页；二分查找、只读统计、搜索和 join 借用数组或切片视图。完整替换不再先复制将被丢弃的旧值，clear 一次删除范围。
- varip 恢复的待遍历队列只保存轻量引用，内联 UDT 和 tuple 原地提取嵌套引用。已验证类型的标量数组导入后跳过元素扫描，避免临时复制十万元素；普通字段回滚和 slice 父链保持原语义。
- 历史树顺序迭代使用叶游标和子树栈；`nth` 保留按索引定位。同叶裁剪只推进逻辑窗口，完全过期的子树使用空标记，减少重建空分支链。

差分扫描还发现并修复两条旧错误路径：裁剪已删除绘图后，仍被变量或数组引用的合法旧句柄会报无效 ID；保留窗口下，形成中变化会让增量副本残留旧快照。现在旧句柄沿用各族已删除对象的 Na 或 no-op 语义，未分配 ID 仍报错；保留窗口内仅对发生变化的对象替换其当前显示投影。

## 交错测量结果

新旧探针使用相同源码、输入、Rust 1.97.1 和 `-O -C lto=thin -C codegen-units=1`。每项新旧各三个新进程，交错执行并反转中间一轮的顺序；每个实时进程测量 31 次增量更新和 31 次完整快照更新，以下取各进程中位数的中位数。测量期间没有同时编译。

| 负载 | 增量更新时间 修复前 | 修复后 | 单次累计分配 修复前 | 修复后 |
| --- | ---: | ---: | ---: | ---: |
| 16,384 bars，每 bar 新建 label，活动上限 1 | 3.8500 ms | 0.1261 ms | 2,442,011 B | 19,327 B |
| 十万元素数组，修改一个值 | 2.5463 ms | 0.0209 ms | 3,212,456 B | 22,888 B |
| 十万元素数组，二分查找 | 2.1779 ms | 0.0082 ms | 3,208,968 B | 8,968 B |
| 十万元素 varip 数组，修改一个值 | 5.1792 ms | 0.0237 ms | 7,214,768 B | 25,208 B |
| 一万长字符串数组，修改一个值 | 0.8326 ms | 0.0237 ms | 957,866 B | 25,474 B |

同一 16,384 bars 绘图负载的 checkpoint 新分配从 **658,032 B 降到 2,672 B**，耗时从 0.1205 ms 降到 0.0015 ms。保留 64 根已确认 bar 时，seed 后保留堆从 **1,609,455 B 降到 959,623 B**。这些是计数分配器的堆和分配指标，**不是进程 RSS**。

存在明确取舍：该绘图负载的完整快照更新从 24.6791 ms 增到 25.9457 ms，约慢 5%；历史执行从 101.2889 ms 增到 116.9660 ms，约慢 15%。保留窗口下的增量更新从 0.0135 ms 增到 0.0202 ms。持久化树增加了固定路径和对象间接访问，同时保留窗口现在执行修正后的显示语义；本轮没有单独分离各项因素的因果贡献。无限保留时的历史执行保留堆也由 40,046,117 B 略增至 40,451,637 B。

原始分组测量与发现回退后追加的交错测量均保留，以交错测量作为上表依据：[交错结果](../.local/state-performance-20261003/paired-comparison.json)、[原始逐轮数据](../.local/state-performance-20261003/perf-paired.jsonl)、[首次分组对照](../.local/state-performance-20261003/performance-comparison.json)、[探针与库身份](../.local/state-performance-20261003/probe-provenance.json)。

另用执行探针交错运行新旧版本，每版三个新进程、每进程三个循环。深度 5,000 的 50,000 次直接历史提交中位数从 29.3342 ms 降到 4.8955 ms；相同深度的 50,000 bars 完整脚本从 256.5885 ms 变为 252.1057 ms，整体基本持平，不能把局部约六倍的改善外推为整个解释器六倍加速。各深度及变量负载结果见 [历史执行对照](../.local/state-performance-20261003/paired-execution-comparison.json)。

公共 API 差分覆盖 111 个脚本乘两种保留模式，共 **222 组全部通过**。每组包含 257 根 seed 和 8 根 bar 的三次形成中更新及一次确认；保存 7,326 份快照指纹，并在 7,104 次更新后逐步检验增量副本等于完整快照。旧版通过的 193 组共 **6,369 份完整输出逐字节一致**；旧版失败的 29 组现已通过，其中 6 组是旧句柄错误，23 组是副本不一致。见 [差分核对](../.local/state-performance-20261003/differential-comparison.json)，原失败凭据未覆盖。

## 尚存成本

- 请求完整快照时仍须复制全部公开历史及字符串，数据量和耗时随保留历史增长；增量路径的加速不代表完整输出也等幅加速。
- 大数组首次写仍复制 O(N/128) 个页指针及最多 128 个值，不能称严格常数时间。中间插入、删除、array.copy 和历史副本等批量操作仍可能完整物化。
- 历史树顺序遍历为 O(N 加树高)，跨叶裁剪访问边界路径；一次大量回收仍有与释放量相关的析构成本。GC 仍需追踪实际可达图。
- 持久化 ID 树仍有固定路径开销；无输出 seed、Python GIL、部分 TA 算法及其它未测负载不属于本轮已验证改善。

以上是限定脚本和输入下的语义及性能证据，不是任意 Pine 脚本、无限会话或真实宿主负载的性能保证。
