# Supertrend ATR with Trailing Stop Loss v4 admission audit (2026-09-24)

[The public TradingView script by exit490](https://www.tradingview.com/script/L9GkARD2-SUPERTREND-ATR-WITH-TRAILING-STOP-LOSS/) has about 5,000 boosts in the observed publication UI. Its complete 267-line Pine v4 source was read from the visible Source code panel and preserved at `.local/community-coverage-20260923/exit490-supertrend-atr-tsl-v4.pine` (SHA-256 `03f6dba66131da03157e5820f3820297af38fc2ba2f9c1721f56df3ad2a6e3c1`). The raw accessibility snapshot is also retained there. The source declares `calc_on_order_fills=true`, `calc_on_every_tick=true`, USD account currency and 100% equity sizing, and uses strategy orders inside user functions.

The publication's embedded daily strategy report showed 13 trades. On the signed-in `BINANCE:BTCUSDT` chart, the original study executed in both 1h and 1D intervals. The daily trade-list export `I:\sys\下载\SUPERTREND_ATR_WITH_TSL_BINANCE_BTCUSDT_2026-09-24 (1).csv` (SHA-256 `6e97250ca73f5ab7f59d504256c8150907c1a1148da214a603bd897a8656d711`) contains 252 entry/exit rows for 126 numbered trades, including the final open trade. The daily chart export `I:\sys\下载\BINANCE_BTCUSDT, 1D (26).csv` (SHA-256 `604f53b2d567de18be64b404fb0e6b28d3e1f7cde51e28abbf709c307cedf307`) contains 2,234 OHLC rows from August 2020 through September 2026. It is **not** the full input history behind trades starting in January 2019. The chart was returned to its original 1h interval, the temporary strategy was removed, and the layout was saved.

At the initial audit, the interpreter did not admit the complete source. Its pre-change `pine-compat analyze` reported 15 diagnostics across four independent issues:

1. The old `strategy(..., linktoseries=true)` declaration parameter is not recognized.
2. `strategy.close(id, when=true)` is not recognized, although TradingView's [v4 strategy documentation](https://www.tradingview.com/pine-script-docs/v4/essential/strategies/) explicitly uses `when` for close orders.
3. Strategy entry and close calls inside user-defined functions were rejected. The analyzer now allows strategy order calls in user functions, and a focused v4 runtime regression verifies an entry and close fill on their expected bars. This audit does not claim full-source admission.
4. The published source repeats the `transp=0` named argument on each of two `plotshape` calls. The local analyzer rejects the duplicate, while the native published script executes. Whether the current Pine editor accepts the exact source on recompile has not been independently tested.

The script's USD account on a USDT chart also needs a host-supplied historical currency conversion path for trade quantity and PnL parity. A same-currency `BTCUSD` chart can isolate execution behavior first. The initial Binance exports alone did not establish plot, trade, or accounting parity. The date range, input history and forming-bar boundary must be matched before comparison.

After the function-order change, a rebuilt CLI reports seven diagnostics: one `linktoseries`, four repeated `strategy.close(when=...)` reports from the two written calls, and two duplicated `plotshape(transp=...)` reports. It reports zero unsupported features, but emits no executable HIR until these call errors are resolved. `cargo test -p pine-sema -p pine-runtime --lib --locked --quiet` passed 1,244 semantic and 1,878 runtime library tests; `cargo fmt --all -- --check` and `git diff --check` passed.

## Follow-up: historical fill rollback

To expose the script's otherwise sparse `plotshape` data, a separate diagnostic copy replaced the `Entry Price` and `Stop Loss` shapes with `plot` calls. The current TradingView v4 editor rejected the published `type=input.bool` declarations, so this diagnostic copy also removed those two explicit type arguments; the default boolean values remain. The diagnostic source is `.local/community-coverage-20260923/exit490-supertrend-atr-tsl-v4-debug-stop.pine` (SHA-256 `4a9352841460d65dbff1de06f155f454fab4435ac64a29f20e704faee8bf1ef7`). It compiled and ran in the current editor. It is **not** an exact-source recompilation, and the native trade export above remains from the published study rather than this copy.

The native diagnostic chart export `I:\sys\下载\COINBASE_BTCUSD, 1D (5).csv` (SHA-256 `4aa9c618d6ad8fbffba3ddc396cd0f4254adb07db4ba7f20b2b506d22c5985a4`) contains 2,766 rows, of which 2,764 align with local bars. It shows `entryPrice` and `stopLossPrice` become empty after the fourth trade's closing order, including the fifth trade's 2019-04-12 entry. This establishes why the former local run's newly initialized stop caused a premature fifth exit. The runtime's strategy evaluation checkpoint restored ordinary series state but omitted persistent `var` slots. It now restores `var` slots before each fill-triggered historical script pass while preserving `varip` values. Separate regressions verify both behaviors. This matches TradingView's documented [rollback and `varip` exceptions](https://www.tradingview.com/pine-script-docs/language/execution-model/).

After that correction, the complete normalized script's output `.local/community-coverage-20260923/exit490-supertrend-atr-tsl-v4-btcusd-after-var-rollback.json` (SHA-256 `a663add26aff10b81e19f071985e223688bdda6b8403192d0836529727d92779`) has zero diagnostics and 120 closed trades. The first **21** indexed trades agree with the published native trade export on entry and exit dates and prices; the fifth now exits on 2019-06-05 at USD 7,671.07. For each of `Debug Entry Price` and `Debug Stop Loss`, the 645 aligned rows with values on both sides match numerically within `1e-7`; 32 dates have a native value but no local value. The next trade divergence is number 22 on 2020-06-02, where native reports multiple trades on one historical bar. No full strategy trade parity is claimed. The five-crate test command passed again, including 1,882 runtime library tests, 1,244 semantic library tests, and 2,248 semantic fixture tests; formatting and diff checks passed.

The next local fix processes a market close at the historical open when an entry fill and its immediate recalculation create that close. It has a focused runtime regression derived from the published trade number 22: native both enters and exits on 2020-06-02 at USD 10,208.96. The new local output `.local/community-coverage-20260923/exit490-supertrend-atr-tsl-v4-btcusd-after-open-close.json` (SHA-256 `aacdf7e7455b0854799309dc54f7fa90f1c1bb464d2c8cf6f6b5f4ee837d9036`) has 122 closed trades and the first **22** indexed trades agree with the published export. Trade 23 remains different: native enters at the 2020-06-02 high of USD 10,237.60 and exits at that day's low of USD 9,270, while local first enters again on 2020-06-03. A generic attempt to fill all same-bar market orders at subsequent OHLC vertices produced an extra 2020-06-02 close-entry trade and broke existing runtime tests; it was removed. Native timing at these later historical ticks requires a more precise scheduler model. The 1,883 runtime library tests pass after removing that attempt.

The historical fill scheduler now gives orders created by fill recalculations a market fill opportunity at the high and low, but leaves orders created after the low for the next bar's open. This follows TradingView's [v4 broker emulator example](https://www.tradingview.com/pine-script-docs/v4/essential/strategies/), which shows two fills at the open and one each at the high and low. The focused v4 regression covers open → high → low → next open; the affected v5 average-price exit snapshot was updated to reflect a same-bar replacement entry. The complete normalized script now produces `.local/community-coverage-20260923/exit490-supertrend-atr-tsl-v4-btcusd-after-hilo.json` (SHA-256 `8f1f0e8848e4e2dfde474a07a79991aaeef05a2db017fc6ea02da14e334f5291`), with zero diagnostics and **127 closed trades**. All 127 indexed trades match the published native export on both entry and exit UTC dates and prices to USD 0.01; the native 128th trade is open, and local has its 2026-09-19 entry at USD 80,875.04. This is **trade timing and price parity, not financial parity**: local quantity already differs materially on trade 3 (0.251611 versus native 0.257308), and the local open quantity is 0.110989 versus native 0.118397. Five-crate tests passed after this change, including 1,884 runtime library tests; log: `.local/community-coverage-20260923/full-suite-after-hilo.log`.

The quantity follow-up distinguishes market orders that remain pending into the next bar from default percentage-of-equity orders filled on their creation bar. The latter resolve quantity against the same-bar fill price and equity. A focused v4 regression uses a gap from a creation close of 10 to the next open of 12, then a same-bar high fill at 13: the first order retains `1000 / 10` units, while the high fill receives `1000 / 13` units. On the complete native comparison, `.local/community-coverage-20260923/exit490-supertrend-atr-tsl-v4-btcusd-after-same-bar-qty.json` (SHA-256 `fdf1283e8e9d1df01f509d30db796bc57df8801eeabc42fb9613a3ba1d6e1f87`) still matches all 127 closed trades on entry/exit dates and prices. Every closed entry quantity is within `0.00001` of the native six-decimal export (maximum absolute difference `0.000001835`); the open 128th entry quantity is `0.11839754` locally versus `0.118397` reported. Individual trade PnL is within USD 0.01 for 121 of 127 trades; maximum difference is USD 0.0342, and final closed cumulative PnL is USD 8,575.4058 locally versus USD 8,575.37 reported. Financial parity to the cent is therefore still unproven. The five-crate suite passes, including 1,885 runtime library tests, 1,244 semantic library tests, and 2,248 semantic fixtures; log: `.local/community-coverage-20260923/full-suite-after-same-bar-qty.log`.

## Follow-up: host quantity precision (2026-09-25)

The native `COINBASE:BTCUSD` trade export reports six decimal places for order quantity. Rerunning the same normalized v4 source and 4,280-bar input with the host-provided `--chart-quantity-precision 6` produces `.local/community-coverage-20260923/exit490-supertrend-v4-qty6-20260925.json` (SHA-256 `c0b082b0ed175d3a2e4e2103293650c67012dbab3dd21b66951b81f900215d89`). Reproduce from the repository root:

```powershell
$b = '.local/community-coverage-20260923'
target/debug/pine-compat.exe run "$b/exit490-supertrend-atr-tsl-v4-duplicate-transp-normalized.pine" --bars "$b/btcusd-bars.csv" --chart-symbol COINBASE:BTCUSD --chart-timeframe 1D --chart-quantity-precision 6 > "$b/exit490-supertrend-v4-qty6-20260925.json"
```

All **127 closed trades** match the native report on entry and exit UTC date, price, and six-decimal quantity. The open trade 128 also enters at the native price (`80,875.04` USD) with the exact displayed quantity (`0.118397`). Closed cumulative PnL is `8,575.373808` USD locally versus `8,575.37` displayed natively. Of 127 per-trade net PnLs, 126 are within `0.005` USD of the native two-decimal value; trade 105 differs by `0.00500176` USD (`-679.85500176` locally versus `-679.85` displayed). The report therefore establishes quantity parity at exported precision and accounting agreement to roughly one cent, while exact internal-ledger equality remains unverified. A v1–v6 regression covers host quantity-grid rounding of percent-of-equity `strategy.order` at same-bar fills; the default host context still preserves unquantized quantities.
