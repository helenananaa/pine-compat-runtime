# Historical tuple `request.security_lower_tf` (2026-09-25)

The three-positional-argument historical request subset now accepts a tuple of scalar expressions in Pine v5/v6 and returns a tuple of typed intrabar arrays. Each array contains its field's values in ascending intrabar time; chart intervals without requested bars receive empty arrays. The host supplies timestamped requested bars through `RequestEnvironment`, and the core evaluates the expression in a separate requested context.

The semantic analyzer derives each tuple element type. Lowering carries those types by request callsite into the HIR so runtime can construct the correct typed arrays even when the current chart interval is empty. UDF tuple results use the same path. The tracked `security_lower_tf_tuple.pine` fixture exercises a UDF returning float and bool fields; its runtime test covers multiple intrabars, a later interval, and an empty interval. A CLI run against the tracked 5-minute chart and host-provided 1-minute request CSVs returned plot series `[[3,2],[3,2],[22,24],[1,1]]` with no diagnostics; the JSON output is retained in ignored `.local/community-coverage-20260923/lower-tf-cli-tuple-20260925.json`. Optional request policies beyond named `calc_bars_count`, collection fields, reference graph transfer, and provider-backed forming updates remain outside this subset.

This addition has repository execution evidence only. No TradingView numerical export for this tuple fixture has been compared yet. The full locked seven-package test output is retained in ignored `.local/community-coverage-20260923/lower-tf-tuple-seven-package-tests-20260925.log`.
