# LazyBear Schaff Trend Cycle v1 native parity (2026-09-25)

The open-source [Schaff Trend Cycle (STC)](https://www.tradingview.com/script/dbxXeuw2-Indicator-Schaff-Trend-Cycle-STC/) by LazyBear has no version directive, so it executes as Pine v1. The original source shown in TradingView's Source code tab was copied to ignored `.local/community-coverage-20260923/lazybear-stc-original-v1-20260925.pine`, with blank lines omitted and function indentation restored. The script places `input(0.5)` inside a user function and uses four self-historical local declarations (`f1`, `pf`, `f2`, `pff`). These are part of the original versioned behavior; the source was not rewritten to avoid them.

The local analysis now reports zero diagnostics and zero unsupported features. The fix allows legacy v1/v2 input declarations inside user functions and predeclares each v1/v2 self-historical local just before analyzing that declaration, after earlier locals have acquired their actual types. The v3 input-in-function rejection remains, and translator revision 36 invalidates prior cached analysis. A focused v1/v2 runtime test covers a function-local input, a preceding `lowest` result, and a local history recurrence. A semantic test keeps the v3 boundary explicit.

Native chart data was exported from TradingView on `COINBASE:BTCUSD` 1D with default inputs (`length=10`, `fastLength=23`, `slowLength=50`, `factor=0.5`), from `I:\sys\下载\COINBASE_BTCUSD, 1D (16).csv` to ignored `lazybear-stc-native-v1-20260925.csv`. The local run uses 4,282 confirmed daily bars, excluding the current forming bar. `compare_stc_v1_20260925.py` checks time and OHLC alignment and reports **zero blank or numeric differences across all 4,282 `Schaff_TC` plot values** at `1e-8` relative/absolute tolerance. Maximum absolute numeric difference is about `1.11e-10`.

This qualifies the original script on the named daily chart with default inputs. Other symbols, intervals, input overrides, and realtime forming updates need separate evidence.
