# 历史容量与 valuewhen 检查点修复（2026-10-05）

修复两处随历史长度增长的开销，并修正 wasm32 对超大 occurrence 的整数截断。本机受控样本中，百万窗口的 public profile 从 23.3172 → 0.0628906 µs/次，十万事件的 forming 无输出更新从 2.1517 → 0.0074 ms。收益属于这些 API 和输入，不能换算为解释器整体加速倍数。

基线 `2688c13b1f24e335b30c55883dc4d523c848d98e`；冻结基线 6321 份源码和 311 份编译产物，最终 6324 份源码用于两平台完整门禁、release 构建和探针链接。本轮源码与测试共修改/新增 11 个文件；本报告两文件在门禁后生成，不在该源码快照中。

## 修改与语义

- AppendHistory 在分支维护物理叶 Vec 容量合计，capacity() 读取缓存。push、compact repeat、前后裁剪、re-root 和 COW 叶克隆均更新缓存；COW 导致容量缩小后，在返回可变元素引用前传播。叶容量使用真实 Vec::capacity，合计饱和加法覆盖 ZST。
- valuewhen 尚未晋升的短历史（保留事件数 ≤128）继续使用 VecDeque；超过边界后将值移动到持久化 AppendHistory，晋升后裁剪不主动降级。长历史克隆共享根；首次写入复制至多 128 个事件值及树路径。读取仍按真实条件事件的 occurrence，保留原求值次序、每次 true 调用事件、false 不裁剪、forming 回滚和确认提交语义。
- `usize::try_from(occurrence)` 后才检查现有 1,000,000 occurrence 上限，防止 wasm32 将 2^32、2^32+7 转成 0、7。静态非法 occurrence 不保留事件；动态非法读取仍保留历史，结果为 NA。
- GC 只遍历逻辑保留事件。裁剪边界的共享物理叶最多留有 127 个过期事件值，它们不作为 GC roots；拥有的字符串/tuple 载荷可能延迟释放到整叶过期。valuewhenStateValueCapacity 反映真实物理槽容量，允许与旧 VecDeque 不同，公开 102 字段 schema 不变。

## 失败、排除与证据绑定

- 首次 baseline 冻结助手因 Windows 反斜杠与旧 receipt 正斜杠索引不一致而 KeyError；发生于任何生产修改/构建/探针前，旧助手和失败文本已封存，规范路径后完整重新冻结。
- 两次 after 链接在执行上下文丢失后只留下 running receipt、空 stdout 和部分 COFF objects；未取得 exit/identity，不视为完成。封存这些产物后仅重新链接，两份新 receipt 和真实退出码 0 通过；中断链接没有资格性能进程。
- 第一批 valuewhen 15 个 Rust 子进程都 exit 0，但 Python guard 错将累计 strategyScriptPasses 等同保留 bars；18 次 forming 执行的 telemetry 不随事件回滚。修正为 seed bars、confirmed/final bars+18 后，对旧 15 stdout/180 public payload 做纯数据复核；该复核没有新探针/计时。整批 15 仍全部排除，随后统一修正版 runner 全新执行 54 个进程。最终合格 108，实际尝试性能进程 123；报告不使用首次 15 的性能。
- 独立审计助手第一次将进程外层 wallSeconds 必须 >0 作为额外断言，empty-after-0 的单次时钟差恰为 0.0，Rust 子进程 exit 0、全部实际 profile 分组时间 >0。封存首次助手/trace 后改为有限非负，仅重新解析同一 108 个进程数据，没有新探针、计时或门禁；最终成功审计与失败封存均保留。
- 旧 cached debug WASM 在本轮任何生产编译前封存，用 v5/v6 复现超大 offset 截断，仅属旧行为证据。之前门禁没有记录该 WASM 的 artifact SHA，因此不能建立该旧 WASM 与基线源码的密码学构建绑定；它不进入性能分母。修复后实际 WASM 由当前 canonical gate 验证。

## 剩余技术债与验证边界

- alert delta 链路仍有 tail 临时 Vec、逐条 AlertEvent clone、last_changes 的完整 clone 及 OutputCursor 的 tail copy。后续应先分别测大消息/多告警的无输出更新、apply_update 与结果 clone，并保持 alert 顺序、回滚、版本和 Replica 语义，再决定借用接口或缓存结构调整。当前只确认源码拷贝点，未测/未修。
- 全局保留状态预算尚不统一：单 valuewhen callsite 的 1,000,000 上限仍在，但多个 callsite 的事件保留没有统一总字节合同；现有 committed-series budget 只约束 series_store。需要 host-neutral、确定性的显式资源合同；不能用裁剪 Pine 合法执行状态或 host 服务依赖代替。当前未实施，也不将合法多 callsite 当作违反已有全局上限。

以上是后续优先候选，不是剩余债务的穷举。此前 Math/Array 的二级字符串分派、一般 WMA/HMA 和方差恢复 O(L) 等仍属于待隔离测量/既有数值资格范围；本轮未宣称清零全部技术债。
