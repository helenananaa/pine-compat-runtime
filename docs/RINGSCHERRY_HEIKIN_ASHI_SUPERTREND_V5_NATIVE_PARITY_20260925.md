# Heiken Ashi & Super Trend v5 strategy: native trade comparison, 2026-09-25

The complete 128-line public [Heiken Ashi & Super Trend strategy](https://www.tradingview.com/script/KkA3sgXM/) by RingsCherrY was copied from its TradingView source tab into ignored local evidence as `ringscherry-heiken-ashi-supertrend-v5.pine` (SHA-256 `ad2c672dc532bf5037ab586e01e1286d873bfc14ea1562e319b6de3e6a1eb0ad`). The unmodified source analyzes as executable with zero diagnostics. Its four `request.security(ticker.heikinashi(syminfo.tickerid), timeframe.period, OHLC)` calls require host-provided Heikin Ashi bars. Running without that provider fails explicitly with `missing request data for symbol {"chart":"heikinashi","symbol":"COINBASE:BTCUSD"}`.

For this comparison, the ignored `build_ringscherry_heikin_ashi_bars.py` generated 4,282 daily Heikin Ashi bars from the existing `COINBASE:BTCUSD` OHLCV chart export, using the standard recursive Heikin Ashi open and averaged OHLC close. The provider CSV SHA-256 is `4f1aedfb86b709568f0eadf4135dbc3dabfae86860729b79f9db0883a91f6c5a`. This generation is test adapter work; the runtime still receives synthetic-symbol data through its host-neutral request interface. The native TradingView strategy report CSV, exported at default inputs on `COINBASE:BTCUSD` 1D, is `ringscherry-ha-btcusd-daily-native-trades-20260925.csv` (SHA-256 `39e7032ab488f77772dda0f5b76cf80bed6805e540f355ac5c041446ceb2252e`). All of these source and data files remain ignored.

The interpreter used 4,282 confirmed daily bars from 2014-12-01 through 2026-09-24, `--chart-symbol COINBASE:BTCUSD --chart-timeframe D --chart-price-grid 1/100`, and the generated Heikin Ashi `--request-bars` stream. `compare_ringscherry_ha_native.py` checks all **67 closed trades / 134 CSV rows**. Every trade agrees on direction, entry and exit dates, signals, and displayed entry and exit prices (within 0.0051 USD for the two-decimal CSV). Quantity differences are at most 0.000001037 against TradingView's six-decimal display. The maximum net-PnL difference is 0.011478 USD against its two-decimal display; this is a comparison tolerance, not a claim of exact internal account-equity parity. The local run has zero diagnostics. The complete batch and incremental JSON outputs are equal. `cargo test --workspace -q` and `cargo fmt --all -- --check` pass after the broker changes.

The native comparison exposed two broker-emulator issues, now covered by focused tests:

1. `strategy.exit(profit=...)` can receive a fractional number of ticks. TradingView's 67 native fills show relative profit targets advanced to the next attainable tick. The broker now rounds the relative distance up to a whole tick, while preserving already-integral distances.
2. When a pending entry reverses an open position and its `strategy.exit` targets the new entry ID, the relative exit must wait for the new entry fill before deriving the price and direction. Previously, two reversal trades closed at their entry price because the target used the old position's direction. The broker now defers relative exits for a pending entry with no matching open position.

This qualifies the tested v5 source and default daily trade path. The publication describes an intended `BINANCE:BTCUSDTPERP` 1-hour setup, which was not compared here. The Heikin Ashi feed was generated from exported standard OHLCV rather than independently exported from TradingView. The exact internal quantity and PnL precision, numerical plot history, other inputs/timeframes, and realtime behavior remain outside this receipt. The temporary strategy was removed from the research chart after the export.
