# TA 窗口扫描临时分配修复 — 2026-10-05

基线 `5ace7d93a70cb518843ffae3ca9a0cae90de676a`。本轮只修改纯运行时中的 LinReg/SWMA 扫描及回归测试，没有引入 host 依赖。

## 修复与数值契约

`ta.linreg` 原来每次就绪后先把整个窗口复制到临时 Vec，再扫描计算；`ta.swma` 也为四项值分配 Vec。LinReg 现在直接扫描原逻辑窗口，保持四个累加器的初值、顺序及后续分母、斜率、截距、offset 运算。长度 1 原样返回样本，保留负零等 Float bits。SWMA 使用四项栈数组，表达式与运算分组不变。

普通循环调用仍逐次追加；动态长度、NA、就绪判定、调用点身份和公开输出契约不变。一般 LinReg 仍为 O(length)，本轮消除复制和临时分配，没有使用改变舍入路径的递推或闭式公式。

## 剩余热点与边界

共享检查点后的页端点写入仍复制 `Arc<VecDeque<Arc<Page<T>>>>` 页目录，成本为 O(length/128) 的引用复制。只读源码估算 64 位 Option<Float> 下，取目录和未满尾页均共享、普通追加未跨页边界的案例：目录请求为 48+8×页数 B，另加 40+2048 B 的有界页，共四次请求。取 2/24/782 页的长度 129/3000/100000 示例为 2152/2328/8392 B。页数也受 front_offset 和端点影响，满尾页插入还可能触发目录增长；这些是结构推导的示例，尚非 allocator 实测或所有写入的统一成本。可继续评估独立首尾页和共享中间完整页目录，同时验证小窗口/clone 成本、页边界、动态缩放、历史及保留容量不变量。

一般 LinReg/WMA/HMA/variance 扫描、Map/Matrix 二级分派及递归 HIR 仍需实际归因。本轮无新的测试、门禁、探针或审计失败；补测由慢项触发。未验证 TradingView 数值参考、RSS、host/策略/request 吞吐、完整资源矩阵、跨平台性能或发布资格。
